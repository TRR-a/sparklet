# 版本信息集中化：独立 version.json 单一来源

## 概述

新建独立的 `version.json` 作为版本号 + 内部代号的**唯一权威来源**，构建时由脚本同步到 `package.json` 并生成 TS 常量；about 面板等显示版本的地方运行时从常量/IPC 读取，**摆脱每次升版本要改 9 个 locale + about.html 共 10 处硬编码的痛点**。

## 现状分析

当前版本信息分散在 4 类位置：

| 位置 | 内容 | 问题 |
|---|---|---|
| `package.json` L3/L5 | `version: "0.2.3"`、`internalCodename: "Mist"` | Electron `app.getVersion()`、electron-builder、npm 依赖此字段（不可移除） |
| 9 个 `modules/note/shared/locales/*.json` | `about.version` / `about.internalVersion` 硬编码 | 每次升版本要手改 9 处 |
| `modules/note/about/about.html` L19-L20 | 静态回退文本硬编码 | 第 10 处；L24-L26 的 Electron/Node.js/NW.js 版本也是硬编码（Electron 实际是 40.10.6 而非 40.0.0；NW.js 是历史遗留错误行——本项目是 Electron 应用） |
| 运行时代码 | `check.ts:13` require package.json 读 version；`generate-manifest.js:31` 读 package.json 的 internalCodename | 依赖 package.json，与用户想要的"独立文件"不符 |

## 方案设计

### 1. 新建 `version.json`（项目根）— 唯一权威来源

```json
{
  "version": "0.2.3",
  "internalCodename": "Mist"
}
```

### 2. 新建 `scripts/sync-version.cjs` — 构建时同步

- 读 `version.json`
- 写回 `package.json` 的 `version` + `internalCodename`（Electron/electron-builder/npm 继续工作，**这两个字段变成同步产物而非手工维护项**）
- 生成 `src/shared/app-info.ts` 常量文件（编译进 build 树，主/渲染进程均可 import，运行时零文件依赖）：

```typescript
// Auto-generated by scripts/sync-version.cjs from version.json — do not edit [由 sync-version.cjs 从 version.json 生成，勿手改]
export const APP_VERSION = '0.2.3';
export const APP_CODENAME = 'Mist';
```

### 3. package.json 脚本挂载

```json
"sync-version": "node scripts/sync-version.cjs",
"build": "npm run sync-version && npm run build:vendor && npm run build:main && npm run build:renderer && npm run build:copy"
```

`generate-manifest` 链最前也加 `npm run sync-version &&`（保证 manifest 的 codename 用最新值）。

### 4. 主进程：改用常量 + 新增运行时版本 IPC

- `src/main/updater/check.ts` 的 `getCurrentVersion()`：`require('../../../../package.json')` 改为 `import { APP_VERSION } from '../../shared/app-info'`（消除运行时 require JSON）
- `src/main/ipc/window-ipc.ts` 新增：

```typescript
ipcMain.handle('get-runtime-versions', () => ({
  electron: process.versions.electron,
  node: process.versions.node,
}));
```

- `generate-manifest.js` 的 `getPackageInfo()`：internalCodename 改为读根目录 `version.json`（脚本运行在项目根，直接 `fs.readJson`）

### 5. 渲染层：about 面板动态填充

- `src/renderer/core/window-api.ts` 加：

```typescript
getRuntimeVersions(): Promise<{ electron: string; node: string }> {
  return bus.invoke('get-runtime-versions');
}
```

- `modules/note/Pages/about/about.ts`：
  - `import { APP_VERSION, APP_CODENAME } from '../../../../src/shared/app-info.js'`（tsc 会把该依赖编译进 build，tsconfig.main 的 include 已覆盖 `src/shared/**`，渲染层经 import 依赖链同样编译，常量文件无副作用，双 tsconfig 输出一致）
  - `loadThemeAndI18n()` 后填充：版本行 `t('about.version', { version: APP_VERSION })`、内部版本行 `t('about.internalVersion', { codename: APP_CODENAME })`（i18n.ts 的 `t()` 已支持 `{占位符}` 参数替换，见 i18n.ts L93-L99）
  - Electron/Node.js 行：调 `windowApi.getRuntimeVersions()` 填充实际运行时版本
  - **删除 NW.js 行**（历史遗留错误信息，本项目无 NW.js 依赖）

### 6. locale 模板化（9 个文件）

`about.version` / `about.internalVersion` 从硬编码值改为占位符模板：

| 键 | 改前（zh-CN） | 改后 |
|---|---|---|
| `about.version` | `"版本 0.2.3"` | `"版本 {version}"` |
| `about.internalVersion` | `"内部版本: Mist"` | `"内部版本: {codename}"` |

其余 8 语言同理（en: `"Version {version}"` / `"Internal Version: {codename}"`，依此类推）。

删除不再使用的键：`about.electronVersion` / `about.nodeVersion` / `about.nwjsVersion`（HTML 从未通过 data-i18n 引用过这三个键，Electron/Node 改为纯 JS 填充数字，无翻译文本）。

### 7. about.html 调整

- L19/L20 静态回退文本保留（JS 加载前短暂显示，运行时立即被动态值覆盖）
- L24-L26 版本信息区改为带 id 的空骨架，由 about.ts 填充；删除 NW.js 行：

```html
<div class="version-info">
    <p id="electronVersion"></p>
    <p id="nodeVersion"></p>
</div>
```

## 实施步骤

1. 新建 `version.json`（写入当前值 0.2.3 / Mist）
2. 新建 `scripts/sync-version.cjs`（读 version.json → 写 package.json + 生成 src/shared/app-info.ts）
3. `package.json`：加 `sync-version` 脚本，`build` / `generate-manifest` 链最前挂载
4. 跑 `npm run sync-version`，确认 package.json 无变化（值相同）、app-info.ts 生成
5. `check.ts` 改 import 常量；`generate-manifest.js` 改读 version.json
6. `window-ipc.ts` 加 `get-runtime-versions` handle；`window-api.ts` 加 `getRuntimeVersions()`
7. 9 个 locale：模板化 2 个键 + 删除 3 个无用键
8. `about.html`：版本信息区改骨架 + 删 NW.js；`about.ts` 加动态填充
9. `npm run build:copy` 同步 build 目录
10. 编译验证：`npm run build:main` + `npm run build:renderer` 均 exit 0

## 验证

- `npm run build` 全链通过；`build/src/shared/app-info.js` 存在且值正确
- 手改 version.json 为测试值 → `npm run build` → package.json 与 app-info.ts 同步变化 → about 面板显示测试值 → 改回
- 关于升版本流程变化：以后只需改 `version.json` 一处，`npm run build` 自动同步其余所有位置

## 假设与决策

- **package.json 的 version 字段保留**：Electron `app.getVersion()`、electron-builder、npm 强制依赖，无法真正移除；改为 sync 脚本自动同步，不再手工维护
- **`updater-config-ipc.ts:69` 的 `app.getVersion()` 不改**：Electron 语义正确，sync 脚本已保证 package.json 同步
- **选 TS 常量而非运行时读 version.json**：version.json 不会进 electron-builder 的 asar（files 列表仅 build/**/*），运行时读文件需要额外打包配置；编译期生成常量零运行时成本
- **删除 NW.js 行**：本项目是 Electron 应用，NW.js 显示是错误的历史遗留
- 完整性校验（filesHash）不受影响：app-info.ts 编译产物在 build 树内，正常参与校验；version.json 不进包
